10 Core Processes

Follow each workflow from initiation to completion, including who acts, who approves and what happens when a request is rejected.

01

Admission — Student Enrollment

7 steps · 5 approvers · The flagship multi-stage enrollment workflow
Open live

What it does: Takes a prospective student from initial application to assigned roll number and house master record. Five designated authorities must approve sequentially; a rejection at any gate returns the file or terminates processing.

Process Flow
AO sends link → Parent submits → AO validates docs → Fee Payment → Accounts confirms → OS allocates Roll/House → VP approves → Principal signs → Student Master Created
Sequential Steps
01
Admission Officer Log in as → Admissions → dispatch application link to parent.
02
Parent Log in as → access form → complete documentation & submit credentials.
03
Admission Officer Log in as → verify certificates. If compliant → Validate; if deficient → Return to parent with deficiency memo.
04
Accounts Fee intake: parent completes online gateway transaction, or records offline receipt → Fee Approval issued.
05
Office Superintendent Log in as → Allocate → assigns official Roll Number and House affiliation.
06
Vice Principal Log in as → Review academic eligibility → Approve. (A send-back action expunges assigned Roll and House).
07
Principal Log in as → provide electronic signature certification → Confirm. Enrollment finalized.
Rule
Each step enforces role-based permission boundaries. Every decision (Approval/Rejection) requires mandatory audit remarks. The Principal dashboard aggregates the school-wide pipeline queue in real time.
Verified
Workflow fully validated: end-to-end multi-approver chain, fee transaction confirmation, roll number revoking on send-back, and automated student-master generation.
02

Attendance — Daily Roll Call & Alerts

Classroom marking · Real-time parental SMS/email dispatch · Statutory registers
Open live

What it does: Teachers record daily classroom roll calls (Present, Absent, Late, On-Duty). Marking a student absent triggers an immediate automated notice to parents and updates statutory report card percentages.

Process Flow
Teacher marks roll → Absent status logged → Automated SMS/Email to Parent → Defaulter <75% register updated
Sequential Steps
01
Class Teacher Log in as → Attendance → Select Class 10A → mark roster → Save.
02
Parent Log in as → Portal → Attendance → absent record reflected in real time.
03
Principal Log in as → review school-wide attendance registers and statutory <75% threshold lists.
Rule
Only authorized teachers, HODs, and administrators can register attendance. Warden, Security, and Parents are strictly isolated. Formula: % = (Present + Late + OD) ÷ (Present + Late + OD + Absent). Approved leave days and public holidays do not penalize scores.
Verified
Batch roll submission, deduplicated notification dispatch, comprehensive registers, and dynamic threshold monitoring tested and operational.
03

Fees — Invoicing, Collection & Receipts

Term fee generation · Gateway payment · Sequential receipt generation
Open live

What it does: Produces term fee schedules for enrolled cohorts, facilitates online and counter collections, prints serialized receipts, and compiles real-time outstanding balance lists.

Process Flow
Accounts defines structure → Invoice INV-2026-0001 → Parent online / counter payment → Numbered Receipt & Status Paid → Defaulter tracking
Sequential Steps
01
Accounts Officer Log in as → Fees → set structure → generate term invoices.
02
Parent Log in as → Portal → Fees → execute online payment (or counter cash payment).
03
Accounts Officer Return to → verify invoice transitions to Paid status → inspect outstanding balances.
Rule
Over-payment validation prevents transactions exceeding the exact outstanding invoice balance. Ad-hoc unauthorized fee discounts are structurally prohibited.
Verified
Continuous sequential receipt numbering, exact ledger balance computation, PDF receipt downloads, and online payment settlement verified.
04

Gate Pass — Campus Departure Authorization

Multi-level authorization · Parent OTP confirmation · Security checkpoint
Open live

What it does: Ensures zero unauthorized departures. Requires sequential approvals from Hostel Warden and Principal, delivers a one-time cryptographic OTP to parent, and verifies validity at gate security.

Process Flow
Parent requests → Warden approval → Principal approval → OTP sent → Guard validates OTP → Checked Out → Check In / Overdue flag
Sequential Steps
01
Parent Log in as → Portal → Gate Passes → submit departure request with schedule and reason.
02
Hostel Warden Log in as → Gate Passes → confirm hostel clearance (Approval 1).
03
Principal Log in as → issue final clearance (Approval 2) → system sends 6-digit OTP to parent.
04
Security Guard Log in as → Gate Desk → enter parent OTP → status transitions to Checked Out. Upon return → Check In (late returns automatically flagged).
Rule
Five consecutive invalid OTP verification attempts will permanently lock the gate pass. Departure is physically and digitally prohibited without verified OTP, regardless of administrative approvals.
Verified
End-to-end chain operational: bcrypt hashed OTP storage, digital QR pass issuance, visitor ledger logging, and real-time SMS/email alerts to parents at every transition.
05

Staff Leave — Quotas & Salary Adjustments

Statutory quotas · Mandatory rejection justification · Payroll docking
Open live

What it does: Staff members apply across categorized leave types; departmental heads or HR adjudicate; days in excess of annual quotas automatically calculate per-diem deductions in the subsequent payroll run.

Process Flow
Staff applies → HOD / HR adjudicates → Approved / Rejected → Over-quota days dock payslip
Sequential Steps
01
Faculty Member Log in as → Leaves → apply for Casual, Sick, Earned, Duty, or Unpaid leave.
02
HR / HOD Log in as (or hod@sainik01.edu) → Approve or Reject (rejection requires mandatory remarks).
03
Principal / Staff Log in as → Staff → "My payslips" reflects automated compensation deductions.
Rule
Self-approval is structurally rejected (HOD cannot approve their own application). Annual allocations: Casual 12 · Sick 8 · Earned 15 · Duty 10. Unpaid leave triggers immediate pro-rata salary adjustments.
Verified
Formula verified: 3 unpaid leave days deducted exactly ₹3,000 from a baseline ₹30,000 monthly salary.
06

Student Leave — Absence Recording & Roll-Call Sync

Parent initiated · Multi-stakeholder approval · Automatic attendance sync
Open live

What it does: Parents request planned student absence through the family portal. Once approved, the academic and hostel registers automatically pre-populate the student status as "Leave", preventing erroneous absent marks.

Process Flow
Parent requests → Warden / Teacher / HOD review → Decision registered → Classroom & Hostel registers sync
Sequential Steps
01
Parent Log in as → Portal → Leaves → file absence request for linked child.
02
Warden / Teacher Log in as (or teacher@sainik01.edu) → Approve or Reject (parent notified immediately).
03
Class Teacher Log in as → Attendance → roster slot is pre-filled as "Leave".
Rule
Only the original applicant (parent) can cancel a filed request, and cancellation is restricted exclusively to requests in Pending status.
Verified
Parent portal submission, overlapping date verification, and automated pre-filling across class and hostel registers fully operational.
07

Exams & Report Cards — Grading & Publish Gate

Assessment setup · Provisional mark entry · Cryptographic publication freeze
Open live

What it does: Department heads define examination criteria; teachers record scores in provisional state; rankings and grade bands are calculated, but results remain completely invisible to parents until administrative publication is authorized.

Process Flow
HOD defines exam → Teacher records provisional marks → HOD / Boss Authorizes Publication → Report Card viewable in Portal
Sequential Steps
01
Department Head Log in as → Exams → configure examination schedule and grading bands.
02
Class Teacher Log in as → input marks (scores are tagged "Provisional" and concealed from students).
03
HOD / Principal Log in as → execute official Publish authorization.
04
Parent Log in as → Portal → Results → report card unlocked.
05
Student (CBT) Log in as → Tests → attempt timed CBT test (server timer, self-grading MCQs).
Rule
The Publish Gate is absolute: before formal publication is authorized, neither parents nor students can access marks. Data leaks of in-progress evaluations are impossible.
Verified
Automatic grading calculations, percentile rankings, print-ready PDF cards, publication freezing, and CBT examination engine confirmed.
08

Payroll — Monthly Compensation Processing

Tax computation · EPF deductions · Strict personal slip isolation
Open live (Payroll tab)

What it does: Executes batch monthly payroll with automated statutory taxes, EPF contributions, and leave docking. Following approval and disbursement marking, employees access only their personal confidential payslip.

Process Flow
HR generates batch → Draft Status → Finalize Batch → Mark Disbursed / Paid → Individual Employee PDF Slip
Sequential Steps
01
HR / Accounts Log in as (or accounts@sainik01.edu) → Staff → Payroll → Generate → Finalize → Mark Paid.
02
Teacher Log in as → Staff → "My payslips" → download encrypted PDF. Isolated strictly to own records.
Rule
Salary data is completely obscured from the public staff directory. Payslips cannot transition to "Paid" without prior formal Finalization.
Verified
Tax slab calculations, statutory EPF, professional tax computations, and leave-docking deduction integrity verified across testing suites.
09

Timetable & Teacher Substitution

Conflict-free matrix generator · Automated faculty substitution logic
Open live

What it does: Synthesizes the institution's complete weekly academic schedule with guaranteed zero room or teacher conflicts. When a teacher logs an absence, the system immediately calculates and assigns substitutions across free periods.

Process Flow
HOD generates schedule → Teacher absent mark logged → Automated conflict-free substitution → Replacement teacher notified
Sequential Steps
01
Department Head Log in as → Timetable → Generate → complete conflict-free grid compiled.
02
Department Head Same session → mark an instructor Absent for today → auto-substitution engine fills affected periods.
03
Substitute Teacher Log in as → "My Day" reflects replacement assignment.
Rule
The substitution engine validates primary teaching load, approved leave, and examination invigilation before assigning replacement duties. Warden and Security have zero access to scheduling modules.
Verified
Constraint-satisfaction solver, batch substitution allocation, daily notice exports, and invigilation assignment tested and live.
10

Discipline & Safeguarding — Confidential Incident Management

Universal reporting · Three-person access boundary · Immutable audit logs
Open live

What it does: Any faculty member can report a student safety or disciplinary incident. Once submitted, it converts into an encrypted dossier accessible strictly to three designated safeguarding officers, with every read event logged to an immutable audit record.

Process Flow
Any staff member files report → Incident encrypted & logged → Case Team: Review → Close → High/Critical triggers immediate alert
Sequential Steps
01
Reporting Staff Log in as → Discipline → report incident. The reporter can subsequently view only their own filed note.
02
Discipline Officer Log in as → access confidential dossier → conduct inquiry → Close.
03
Principal Log in as → reopen closed dossier (justification required) or archive.
04
Isolation Test Log in as — despite full administrative authority elsewhere, the discipline records are completely absent.
Rule
Access restricted strictly to super_admin, principal, and safeguarding lead. Confidential notes are cryptographically prevented from entering any parent notification; all file inspection timestamps are logged.
Verified
Incident lifecycle handling, severity escalation routing, row-level confidentiality enforcement, and immutable audit logs verified.

System Architecture

The 4 Core Operating Rules

Architectural principles governing security, tenant isolation, and procedural integrity across the Genesis Lumia School ERP.

01

Right Person, Right Access

Navigation controls, screens, and action triggers render strictly for roles with explicit permission. Server-side middleware re-evaluates role-based access tokens on every API invocation, making client-side bypass impossible.

02

Every Rejection Leaves a Record

No workflow terminates or reverses silently. Every rejection, send-back, or cancellation mandates structured remarks, recording user ID, timestamp, and justification in an immutable audit ledger.

03

Families Only See Their Own Data

Strict tenant isolation separates institutions, while row-level security isolates families. Parents and students can only access records mapped to their authentic relationship IDs, with zero cross-family data leakage.

04

Every Action Has a Consequence

State transitions programmatically trigger downstream updates: classroom absence triggers instant parent notification, approved leave updates attendance registers, and gate passes generate single-use cryptographic OTPs.
